## Why

A user working across several hub workspaces relies on two surfaces to keep track of agent work they are not looking at: the in-session workspace switcher, and the chat's own background-work list. Both under-report today. A workspace whose Claude Code session holds live background work — the chat itself says "1 background task running" — shows in the switcher as merely running, because only an in-flight turn counts as working (GitHub issue #388). When work in another workspace ends, its "working" word simply disappears, so a workspace with a fresh result looks exactly like one where nothing has happened (issue #383). And inside the chat, a running background task or subagent can be stopped but not opened: nothing shows what it is doing, whether it is progressing, or what it has produced — a `/code-review` turn that fans out into background tasks and agents reads as "working" with no sign of what started (issue #385).

## What Changes

- **Background work counts as working.** A workspace's activity summary reports it working while any agent conversation has a turn in flight *or* still holds live background work (a backgrounded command, a backgrounded subagent, a monitor). The composer's own working / background / idle presentation is unchanged; this is the workspace-level summary the hub carries.
- **A running workspace whose work has finished is distinguished from one that is idle.** The hub's activity summary gains a fourth fact, *finished*: set for a user when a running workspace it had observed working goes quiet (not working, nothing awaiting) and that user has not since viewed the workspace's chat; cleared when the user's session page for that workspace reports the chat surface in view, when the session stops, or when new work starts there. Per user: two users watching the same workspace each clear it for themselves.
- **The switcher presents the new state.** A menu entry names a running workspace as `finished` (its own tone, distinct from `working` and `awaiting you`); the collapsed chip carries a finished badge ranked below awaiting and above working. Once the user opens that workspace's chat, the entry and badge clear on every device.
- **Running background work is inspectable.** A running background task in the composer list and a running subagent in the subagents track are selectable. A subagent — backgrounded or in the foreground of a turn — opens as its child transcript *while it runs*, updating as the agent works, headed by what it is doing (Claude Code's model-written progress summary, which Uatu now asks for), its subagent type, elapsed time, tokens and tool uses, with Stop at hand. A backgrounded shell command opens a task view with its command, elapsed time, latest progress, and its output so far from the moment Claude Code makes the output location known, refreshed while it runs. Rows keep their Stop control.
- **What started is visible during the turn, not only after it.** Background tasks and subagents that start mid-turn (the `/code-review` shape) are listed while the turn is still working.
- The session page acknowledges viewing through a small hub-only route; pages served directly by `uatu serve` have no hub and do not acknowledge.
- **The finished state holds while nobody is watching.** The hub observes each running workspace's activity for its own lifetime rather than only while one of the user's pages is open, so work that finishes after the last tab closes is still reported when the user returns; the marks are persisted in the hub state dir, so a hub restart or upgrade does not forget them.
- **A forked skill is inspectable too.** Claude Code runs a skill such as a review command as a fork of itself rather than as a task: its work streams under the launching row from the start, and that row now opens it as a live child transcript, so a skill that fans out is no longer a turn that merely reads as "working".
- A settled agent row shows its summary as prose, not as the raw result envelope.
- The Hub dashboard (running/stopped only), UatuCode Desktop, push notifications, and OpenCode (which has no background-task notion) are unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `hub-live-stream`: "The stream carries a bounded activity summary of the user's other workspaces" — *working* now includes live background work, and the summary gains the per-user *finished* fact with its set and clear rules (the acknowledgement from a viewing page, session stop, new work). The summary stays bounded to those facts.
- `hub-dashboard`: "The switcher surfaces other workspaces' activity" — menu entries and the collapsed chip distinguish a finished-but-unviewed workspace from an idle one, with badge precedence awaiting > finished > working, and the state clears when the user views the chat from any device.
- `claude-code-chat`: "Background tasks are surfaced, stoppable, and wake the model" — live background work counts as the workspace working for the hub; each running task carries what it is doing, how long it has run, and its usage; a running task is selectable and opens an inspection view (a shell task's output so far, an agent task's live transcript). "Subagent runs open as child transcripts" — a subagent's transcript is openable while it runs and updates live; the launching row and the subagents track name a running subagent's progress.
