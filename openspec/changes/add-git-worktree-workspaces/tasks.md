Fix, in order: (1) recomposed every one of those harnesses to share one `PathReservationCoordinator` exactly like `main.ts`, which turned the existing create/retry tests red; (2) gave `WorktreeRegistrar.register()`'s input an optional `fenced` flag — `registerCreatedWorktree()` (`src/hub/worktree-journal.ts`) sets it `true` unconditionally, since its only two callers (`WorktreeService.create()`/`retryRegistration()`) always run it inside a coordinator fence whose `paths` already cover the destination — and `onboarding.configureWorktree()` (`src/hub/onboarding.ts`) skips its own `reserve()`/`release()` when `fenced === true`, relying on the caller's already-held reservation instead of re-acquiring it. `registerExisting`'s own direct, unfenced call to the registrar (external-discovery registration, which holds no outer path reservation) is untouched and still self-reserves — it is its own only guard against a concurrent rename/clone. The existing `console.error` logging the underlying cause in `registerCreatedWorktree`'s catch is kept. Files: `src/hub/onboarding.ts`, `src/hub/worktree-journal.ts`, `src/hub/worktree-registrar.ts`, `tests/e2e/hub-server.ts`, `src/hub/worktree-lifecycle.integration.test.ts`, `src/hub/worktree-api.integration.test.ts`, `src/hub/worktree-onboarding.test.ts`, `src/hub/hub.integration.test.ts`, `src/hub/worktree-journal.test.ts` (updated the `register()` call-args assertion for the new `fenced: true`). Tests (red confirmed twice: once via a hand reversion of the composition fix alone — 37 failures across `worktree-onboarding.test.ts`/`worktree-api.integration.test.ts` with "folder path is reserved by another operation" — and once via reverting the `fenced` mechanism alone against the now-shared harnesses, same failures): the recomposed `worktree-lifecycle.integration.test.ts` create tests, `worktree-api.integration.test.ts`'s `create` → `registered: true` assertions, and `worktree-onboarding.test.ts`'s "creation registers the child stopped…" now pass under the shared coordinator; `scripts/smoke-binary.ts` registers a real temporary Git repository and calls `POST /api/hub/worktrees/create` once (the exact route the dashboard's dialog calls) and asserts `ok: true, registered: true` on the FIRST attempt — this is what the user hit on the compiled binary.
