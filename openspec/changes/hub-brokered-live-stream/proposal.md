## Why

A session page holds three or four long-lived SSE connections — document state, chat inventory, the selected conversation, an open subagent transcript — each proxied one-to-one through the hub to the workspace child. Two things break at that count. Browsers allow six HTTP/1.1 connections per host, shared by every hub tab, so two session tabs with chat open exhaust the budget and every later request stalls (reproduced against the real hub in Chromium and WebKit: after the second tab, a `state` fetch times out and a third tab never loads). And each browser stream costs the hub one outbound fetch to the child, so the hub's upstream connection count scales with tabs rather than with what is watched — which is the pool that filled up under the `v0.6.2` stream leak and queued every proxied request for tens of seconds. Both were reported by users this week as "switching workspaces is slow"; #350 mitigated the second-order symptoms, but the count itself is the defect.

Public `uatu serve` has been deprecated since `v0.5.0` (#218) with "will be removed in a future release", and three stable releases have carried the notice: the hub is the way uatu is run, and `--local` was removed so that every interface has one trust model. This change completes that removal in the same step, because keeping `serve` public for one more release would force the SPA to carry two live transports — the direct per-stream connections for `serve` alongside the brokered stream — only to delete one of them next. One breaking change with one API revision costs less than building a bridge and tearing it down.

## What Changes

- **One live stream per tab, brokered by the hub.** A session page opens a single authenticated SSE connection to the hub at the hub origin. It carries typed envelopes for every topic the page cares about — document state, chat inventory, conversation events, subagent transcripts — with a per-topic cursor so a reconnect resumes each topic independently, and in-stream subscribe/unsubscribe so selecting a conversation never reopens the connection. Per-tab connection cost becomes exactly one.
- **Fan-out instead of pass-through.** The hub subscribes to a child's topics once, on demand, refcounted by interested tabs, and fans events out. Upstream connections become a function of what is watched, not how many tabs watch it, and are released when the last tab leaves. The child's own SSE endpoints become the internal hub↔child protocol.
- **Cross-workspace activity on the same stream.** The stream also carries a bounded activity summary for the user's other running workspaces — running/stopped, an agent working, an interaction awaiting the user — so the in-session switcher shows a live dot and an activity badge without a second tab.
- **Truthful indicators from one source.** The shell's connection indicator reports the hub stream; the switcher chip and menu update from stream events, not only on menu refresh.
- **Lifecycle recovery collapses to one channel.** Page wake-up reconnects one stream and reconciles per-topic cursors; the document, inventory, and conversation recovery paths from `resilient-live-connections` become one.
- **Development runs in the mode users run.** `bun run dev` starts a hub with a checked-in dev config and user, registers `testdata/watch-docs`, and opens it, instead of a bare `uatu serve`.
- **Diagnostics keep their fixed vocabulary.** Stream lifecycle counters and hub diagnostics gain the brokered stream and per-topic subscription outcomes as fixed classes; nothing request-derived enters a name.
- **BREAKING: public `uatu serve` is removed.** The `serve` and `watch` verbs are no longer accepted from a user; `serve` lives on only as the session child the hub spawns, whose startup contract becomes internal. A user-shaped invocation prints the hub bootstrap steps and exits non-zero.
- **BREAKING: the per-stream SSE routes leave the public API.** `/s/<id>/api/events`, `/s/<id>/api/chat/conversations/events`, and `/s/<id>/api/chat/conversations/<id>/events` are no longer proxied by the hub; the child's routes remain as the internal hub↔child protocol only. The workspace API as a whole moves from public to internal in the contract, and the Hub API — now including the live stream — is the sole public surface. This is one revision increment with migration text naming the brokered stream as the replacement.
- The SPA has exactly one live transport. No fallback to direct connections exists, because no mode remains in which the SPA is served by anything but the hub.

## Capabilities

### New Capabilities
- `hub-live-stream`: the hub-brokered live stream — one authenticated multiplexed SSE connection per page, its envelope and topic vocabulary, per-topic cursors and resync, in-stream subscription control, hub-side fan-out with refcounted upstream subscriptions, cross-workspace activity summaries, and the connection-budget guarantees a page can rely on.

### Modified Capabilities
- `hub-service`: "All session traffic is reverse-proxied under the workspace prefix" — live events are no longer proxied one browser stream to one child stream; the hub subscribes to child topics once and fans out, bounding upstream connections by watched topics, and the per-stream SSE routes are not exposed through the hub at all.
- `serve-cli-startup`: public `serve`/`watch` invocation is removed — "Start a local document serve session" becomes the internal child contract the hub relies on, the "Bare serve invocation warns of deprecation" and "Deprecated `watch` alias" requirements are removed, and a user-shaped invocation reports the hub bootstrap steps.
- `api-contract-publication`: "Public APIs have one canonical machine-readable contract" — the public contract covers the Hub API only; the proxied workspace API is reclassified as internal with an explicit, machine-checkable exclusion, and this reclassification is the breaking change that increments the revision.
- `hub-dashboard`: "The workspace switcher chip reflects real session state" — the chip and menu update from the live stream, and the switcher surfaces other running workspaces' activity (live dot, working, awaiting the user).
- `document-watch-index`: live document state reaches a hub-served page over the hub's brokered stream rather than a directly opened `/api/events` connection; reconnection and reconciliation guarantees are unchanged and now stated against the brokered stream.
- `chat-agents`: the merged conversation inventory and its invalidation signal are delivered as a topic on the brokered stream; per-agent isolation guarantees are unchanged.
- `opencode-chat`: "Conversation updates are structured and reconnectable" — conversation events and their cursor/resync semantics are delivered as a topic on the brokered stream; subscribing to a conversation does not open a new connection.
- `sidebar-shell`: "Animate the live connection indicator" — the indicator reports the brokered stream's state and the current workspace's applied state, one source for one chip.

## Impact

- **Client:** `src/shell/events.ts`, `src/shell/live-channel.ts`, `src/shell/recovery.ts`, `src/chat/client.ts` (inventory and conversation streams), `src/chat/ui.ts` (stream ownership, subagent drill-down, lifecycle recovery), `src/shell/hub-nav.ts` (live chip, activity badge), `src/shell/connection.ts`. The direct `EventSource` paths are deleted, not kept behind a mode check: the hub is the only server the SPA is ever loaded from.
- **CLI:** `src/cli.ts`, `src/cli/parse.ts`, `src/cli/output.ts` — `serve`/`watch` refused for users with the bootstrap message; the child invocation (`--exit-on-stdin-close` from the hub) and the repository's own source-run harness keep working; `SERVE_DEPRECATION_WARNING` and its gate are deleted with the mode they guarded.
- **Hub:** `src/hub/server.ts` (new stream route, authenticated by the hub session), a new fan-out broker module under `src/hub/`, `src/hub/proxy.ts` (the SSE routes are refused rather than proxied), stream diagnostics.
- **Child:** the existing SSE routes in `src/server/routes.ts` and `src/server/watch-session.ts` become the internal hub↔child protocol; a small additive child endpoint reports the workspace's activity summary for cross-workspace badges.
- **API contract:** one SSE protocol definition and two operations added to the Hub API; the workspace API removed from the public contract and classified internal in the route-coverage exclusions. One breaking revision: `contract.json`, the OpenAPI version, summary and `x-uatu-revisions`, `version.ts`, and a changelog section with Migration naming the brokered stream as the replacement for the three removed streams and the hub as the replacement for `serve`. CI's compatibility step is run locally before the PR.
- **Dev/test:** `bun run dev` moves to a dev hub (checked-in `dev/hub.json` with a dev user); no bare-child dev script remains. The e2e harness (`tests/e2e/server.ts`) builds child routes directly and is unaffected for child behaviour, but every live-update e2e path runs through a hub.
- **Docs:** README usage rewritten around `uatu hub` alone; `docs/SELF-HOSTING.md` is the only start path; `ARCHITECTURE.md`'s serve/hub split and live-delivery sections updated. `bun test` gains broker unit tests and a hub integration test asserting upstream subscription counts against tab counts.
- **Relationship to other changes:** supersedes the per-stream client recovery machinery from `resilient-live-connections` (still unarchived) without changing its guarantees; independent of `preserve-manual-file-selection` and `improve-chat-responsiveness`. Subsumes the previously planned `remove-public-serve`; no follow-on change remains.
