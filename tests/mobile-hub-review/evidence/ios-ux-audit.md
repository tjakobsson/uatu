## Ranked hypotheses and root-cause evidence (after RED)

1. **Per-entry section composition drives folder inflation.** Prediction: the browse renderer emits one group/header and multiple action rows for every folder. **Confirmed by scan**: `src/hub/mobile/onboarding-flows.ts:99–106` returns `group(d.name, text(...) + action(folder, "Browse folder") + optional Workspace information + Folder actions)` and prepends a five/six-action Location section. `flow-ui.ts:18–19` supplies full action/section primitives. The issue is hierarchy/composition, not a missing global smaller-font rule.
2. **Flat diagnostic composition drives readiness inflation and loses useful context.** Prediction: the detail renderer emits every diagnostic without summary/disclosure or named grouping. **Confirmed in part**: `credential-flows.ts:91–93` inserts all readiness before public facts and Actions; `flow-ui.ts:31` maps every layer/message/status directly into a fact row. **Important correction:** `credential-types.ts:113–117` defines `ReadinessResult` with only layer/status/message. Named tool context exists on `PublicToolReadinessDto` at 119–124, not each credential row. Never infer which tool a repeated row belongs to by order. Preserve anonymous credential diagnostics as such; named tool inspection uses existing tool-readiness data/destination.
3. **Shared navigation placement is independent of the current task.** Prediction: shared flow pages provide top-only Back and no persistent task-primary slot; a route bug might also force add flows into Settings. **Placement confirmed, route suspicion disproven for observed Hub add**: `flow-ui.ts:101–102` inserts Back in a header with home callback. `styles.css:107–112` makes it normal scrolling header content. Dock selection is derived from current route (`frontend.ts:139`); `coordinator.ts:151–158` serializes detail under `currentRoute`. A02 screenshot correctly selects Hub. Preserve this behavior; do not introduce a blanket “detail means Settings” rule while adding a toolbar.

It is not a second copy of an existing control. Row selection remains in the list; long lists scroll naturally into reach. Sheet actions live once in the sheet's lower fixed footer, with keyboard-aware available height. Modal content is the only active interaction layer while open.

## Bounded corrective plan (not implemented)

1. **Presentation primitives only first:** create a compact row/group presentation and shared detail task-footer slot. Move—not copy—the existing Back. Task pages have one canonical primary. Reserve scroll padding for toolbar + dock + safe area; keep errors and focused fields visible with software keyboard. Sheet footers use their existing owner, not a second global commit bar.
2. **Folder composition:** preserve `folder-*`, `manage-*`, `registered-*` callback identities and `browseGeneration`; replace per-folder sections with named row hierarchy targets in one group. Give secondary management a visible, accessible context affordance with folder-qualified name. No long-press-only primary. Keep current path, Git/registration/runtime facts, empty/denied/retry, Up and selection-vs-configuration intent explicit.
3. **Readiness composition:** summarize credential/capability blockers and unknown states before diagnostics. Keep every supplied layer/message/status in disclosure. Named tool summaries use existing named tool DTOs; no assumed tool association for anonymous credential checks. Public identifier/purposes/assignments remain inspectable, not deleted to reduce height. Unlock/Test do not require scrolling through 17 layers.
4. **Action ownership sweep:** use the 27-row map, remove superseded placements in the same change, preserve route/dock context and browser history. Collapse duplicate cancel/back-to-edit meanings without losing draft restoration. Add assertions for exactly one Back/task-primary and reachable viewport geometry on long/empty/error/pending states. Do not force Hub add/clone to Settings merely because they are details.
5. **Regression gate before approval:** run updated REDs to green, existing flows/security/credential/clone-monotonic/continuity suites, then all 27 browser captures plus pending/error/cancel matrix. Explicitly check secret inputs clear at the same moments; validation and callback dispatch are unchanged; busy/unknown outcomes prevent duplicate mutation; auth/presentation generations fence stale responses; retained Files/Preview/Chat/xterm and scroll/input state survive detours. Then WebKit/physical-device keyboard, enlarged text and VoiceOver checks. No API extension or live integrations needed.

No corrective product change is authorized by this diagnosis report alone. RED remains intentional.
